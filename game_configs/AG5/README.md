# AG5 金兔数值配置

初始倍率沿用 Lua 1018。`lua-1018-source.json` 保存来源文件哈希、推导口径和与原流程的差异。修改这些表后，本说明中的初始返还率不再代表修改后的配置。

## 数值表

- `base.json`：单次普通中奖的总原始倍率，包含线奖及本转奖励奖；保留实际运行 `room.lua` 普通表的 1,440 个正倍率及其权重。原表零项迁移到普通中奖率，约 29%。
- `free.json`：单次特殊转中奖的总原始倍率，2,635 档。Lua 的特殊结果表为空，因此按实际特殊开奖过程推导：十格独立、单格 40% 出奖励、本转至少五个奖励才支付全部奖励之和。零奖分离为单次特殊转中奖率 36.68967424%。表内权重是中奖后的条件分布。
- `config.json`：10 线、普通中奖率、特殊单转中奖率、特殊触发率 0.6%、固定 8 转、整局 5,000 倍封顶，以及模拟次数和种子。
- 文件倍率保持原始单位；除以 10 后为总投注倍率。基础线奖公式仍为赔率 × 投注面值 × 投注等级。

特殊面值原始倍率为 5、10、20、50、100、200、500、1000、2000，即总投注的 0.5、1、2、5、10、20、50、100、200 倍。Lua 中原始 5000 面值没有生成权重，不加入初始奖励列表。原面值权重合计略高于随机抽样范围 154126；推导按实际范围截短最后一个区间，记录原始与实际权重。

普通结算后独立判断是否追加特殊功能；八转每转清空，中奖立即支付并继续剩余转数，达到整局 5,000 倍时只支付剩余额度并停止后续转。这个流程遵守已确认的 AG5 规则，与 Lua 中普通、特殊二选一的流程不同。

初始未封顶返还率约 **97.5409892611%**，其中普通 87.5482806469%、特殊 9.9927086142%。页面通过离散分布卷积计入整局封顶，模拟使用相同开奖流程。极低概率尾部的双精度结果不适合作为精确尾部风险估计。

## 开发页与消费约定

`paylines.json` 固定三列 3、4、3 格及十条线，位置编号按列从上往下。每线取最高奖，各线求和；奖励不参加线奖，百搭不能替代奖励。本转五个以上奖励支付所有奖励之和，普通线奖可叠加。图标及奖励生成权重仅影响骨架形态与效率，不影响由倍率表决定的奖金概率。

普通、特殊骨架分别生成，特殊库的单元是一转中奖，不是一段八转。每条骨架格式为 `{"cells":[位置,符号编号,...]}`，位置从 0 开始；只固定计奖必需元素。普通空位实时填普通符号，并重验中奖线及奖金不变；特殊空位保持空白。空奖由后端实时生成，不依赖零倍率桶。特殊功能按每转中奖率独立抽奖，选中正奖后按该表的权重抽倍率，再选对应桶内骨架。

### 一次补齐规则（服务端开发约束）

普通空奖及普通中奖骨架补空均采用“先排除冲突候选，再抽取一次”。每个待填格最多抽取一次，不允许整盘重摇、单格抽错重抽、回溯、修改固定中奖元素、换倍率或换骨架来补救。Go 服务端与数值工具均使用以下规则。

1. 先固定本转已有元素。中奖骨架固定全部中奖线及全部计奖奖励；普通空奖可先在随机位置一次安排 0～4 个奖励符号，再按面值生成权重分别抽取面值。奖励数量不得超过可用格数，位置从未占用位置集合中直接无放回抽取。
2. 普通模式剩余格子按列从上到下依次填写，只使用正生成权重的普通符号，骨架内已有百搭保持不变。含奖励符号的线已被阻断；对其他经过当前格子的线，排除填入后会新增中奖线的候选。
3. 从剩余合法候选中按它们的生成权重抽取一次并落位，随后处理下一格。该过滤仅影响外观，不改变已抽中的中奖率、倍率或奖金。
4. 本转已有五个以上计奖奖励时禁止新增奖励；没有奖励奖金的普通中奖骨架默认仅补普通符号。特殊中奖骨架不再增加奖励，其余位置保留空白；特殊空奖一次安排 0～4 个随机位置的奖励，其他位置为空白。
5. 发布前拒绝存在“两个百搭加一个待填空格”的骨架，并要求正权重普通符号数量大于任意格子经过的中奖线数量。当前为六种普通符号、每格最多经过四条线；每条线至多排除一种普通符号，所以每一步至少还有两种合法候选，不会中途无解。关闭过多普通符号生成权重的配置不能发布。
6. 全部填完后验奖作为一致性断言：中奖结果的线奖明细、奖励奖金及总原始倍率与骨架一致，空奖为零。断言失败属于实现或数据错误，不能重新采样。整局封顶在奖金结算阶段截断，不通过改变盘面奖来处理。

生成器同时使用定向奖励和构造、普通线枚举及自然候选，固定种子可复现。倍率表正权重档逐一检查覆盖；无法构造的倍率显式列出，不调权重、不删除档位。初始配置用 6,000 次尝试、每档保留一条、种子 1018，可完整覆盖普通 1,440 档和特殊 2,635 档；每条通过重放及补空校验。

保存输出 `game_libraries/AG5/base|free/<批次>/library.json`，文件只含原始倍率桶。独立 `manifest.json` 保存数值配置、盘面配置、倍率表、两个版本、数据哈希、覆盖及生成统计。保存前后均检查数值和盘面版本，候选不自动启用。

重新导入可在 `slot_math` 运行 `node tools/import-rabbit-lua.mjs /完整路径/1018/room.lua`，输出用于审核的补丁；已有 AG5 文件时拒绝覆盖，避免抹掉调表结果。Go 服务端已按上述契约实现，本地发布、结算与验证说明见 [AG5 服务端](../../slots_service/internal/games/ag5/README.md)，客户端字段见 [接口文档](../../slots_service/docs/client-api.md#ag5-本地接口)。
