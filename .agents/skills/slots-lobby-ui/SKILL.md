# 大厅加载与失败状态

## 静态内容立即展示

- 页面布局不等待接口：标题、返回、筛选、固定菜单、功能入口、说明文案和已知会话信息直接渲染，不用整页 loading 或整页骨架将它们挡住。
- 先区分静态结构与接口字段，只在昵称、头像、余额、统计数值、记录列表等实际依赖接口的位置展示局部占位；保持这些位置的尺寸稳定。
- “我的”页即使个人资料尚未返回，也立即显示福利中心、账户服务、安全中心、语言和存取款入口；昵称、头像、余额在原位置加载。接口未知金额不能伪装成 0 或可领取金额。
- 已有缓存数据时继续展示，后台更新不清空页面；接口失败也只在对应数据区域展示重试，静态内容与其他成功区域保持可用。
- 验证慢接口和失败场景：不依赖接口的入口始终可见可操作，不能等所有请求成功才一起显示。

## 接口失败

- 数据加载接口失败时，复用 `slots_lobby/src/components/feedback/NetworkError.tsx`，在所属内容区域居中显示“网络异常，请重试”，下面单独显示“重试”按钮。英文随当前语言显示对应翻译。
- 保留页面标题、返回和筛选；使用公共主题按钮、统一间距和响应式居中布局，不能使用裸默认按钮或各页各写失败文案。
- 点击重试只重新加载失败的数据；请求进行中显示 loading 并防止重复点击。不改变现有请求次数、退避和鉴权逻辑。
- 已有数据时保留内容，刷新/分页失败在相应区域使用同一公共错误组件，避免把现有记录清空或伪装成零金额、无数据。
- 余额不足、表单校验、订单已退回等业务状态保留明确业务提示。提交、支付、领取、取款等操作失败不得用通用重试自动重新发起业务操作，保留原幂等请求和结果确认流程。
- 修改后检查中英文、320px窄屏，以及失败后点击重试恢复成功的流程。

## 异步按钮

开发点击后请求接口的按钮时，同时遵守 [async-button-states](../async-button-states/SKILL.md)，保持按钮尺寸稳定，请求中只显示居中旋转的小圆圈。

## Toast 不阻塞页面

- Toast 只作轻提示，透明容器和列表空白区域必须允许点击、滚动穿透，不能锁定页面或触发全屏遮罩。
- 不得用 `#lobby-overlays > * { pointer-events: auto; }` 这类通用规则覆盖消息组件的 `pointer-events: none`；只让实际交互面板、弹窗遮罩和可见通知卡片接收输入。
- 验证 toast 显示期间底部导航和页面按钮仍可操作，同时确认 Modal 的遮罩仍阻止点击背景。

## 操作失败使用 Toast

- 回放、分享、复制、提交、领取等操作失败统一用公共 Toast；禁止在按钮下方、卡片或记录中插入错误文字、Alert，保持布局稳定。
- 保留重试入口，不自动重新提交业务操作，不丢失幂等标识。
- 首次加载失败使用局部 NetworkError；已有内容的刷新、分页失败用 Toast 并保留内容。本条优先于上文已有数据时展示错误组件的规则。
