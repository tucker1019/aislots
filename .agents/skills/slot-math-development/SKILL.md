# slot_math 开发约定

本工具的核心：**先用倍率权重表、中奖率和玩法参数决定奖金分布，再用中奖骨架表现抽中的倍率。** 数值分析和骨架生成是两个独立职责。制定计划、设计新玩法和实现代码时均保持这个边界。

## 配置与产物的职责

| 文件或模块 | 职责 |
| --- | --- |
| `game_configs/<游戏>/base.json`、`free.json` | 对应模式的倍率与开奖权重，供理论计算、模拟及后端抽倍率使用 |
| `game_configs/<游戏>/config.json` | 玩法标识、中奖率、触发率、次数、策略等数值参数 |
| `game_configs/<游戏>/board.json` 或 `paylines.json` | 盘面结构、赔付规则及骨架生成参数，按玩法使用 |
| `game_libraries/<游戏>/<模式>/<批次>/library.json` | 开发页生成、按倍率分桶的中奖骨架 |
| 同批次 `manifest.json` | 配置快照、版本、哈希、覆盖情况和生成统计等元数据 |

- 保留倍率权重表作为数值输入，不能改成从骨架库的样本数量反推开奖概率或 RTP。
- `free.json` 的含义由玩法决定，例如 AG4 表示重转最终倍率分布；不能将其改成“单个奖励符号的面值权重表”，也不能一律解释为传统免费旋转。
- 区分“倍率开奖权重”和“图标、面值、位置等骨架生成权重”。前者控制真实奖金分布；后者影响合法骨架的形态、多样性、覆盖和生成效率，不能越过数值模型决定实际奖金。
- 玩法确实需要额外生成参数时，在适合该玩法的配置中定义并校验，不挪用已有倍率表的含义。

## 数值分析：参数直接控制 RTP

对一个仅含单次开奖、没有额外策略和封顶影响的模式：

```text
中奖后的平均原始倍率 = Σ(倍率 × 权重) ÷ Σ权重
模式 RTP = 中奖率 × 平均原始倍率 ÷ 线数
实际奖金 = 原始倍率 ÷ 线数 × 总投注
```

例如中奖率 30%，中奖后的总投注倍率为 1 倍（权重 80）和 5 倍（权重 20），则这一模式的 RTP 为 `30% × (1 × 80% + 5 × 20%) = 54%`。

- 文件倍率和骨架桶键沿用原始倍率单位，页面可换算为总投注倍率；不能重复除线数或重复乘特殊加成。
- 中奖率与表内零倍率的处理必须在理论、模拟和实玩中一致，不能重复计算未中奖概率。调整既有表的零项语义属于数值变更，不顺手修改。
- 总 RTP 按实际玩法组合：模式替代、额外特殊功能、固定多转、追加、保底、连续策略和奖金封顶分别建模，不能把单模式公式直接当成完整游戏公式。
- 例如 AG4 的普通和重转是二选一；不能因此认定所有新增游戏也二选一。已确认的玩法规则优先于参考游戏代码。
- 有封顶时，理论值和模拟均需计入截断及提前结束的影响；未经处理的期望不能标成封顶后的实际 RTP。
- 数值模拟按同一份数值配置抽中奖与倍率。盘面自然生成的命中率或骨架保留比例，不替代这些配置概率。

## 开发页：生成对应倍率的中奖骨架

生成链路：

```text
玩法与盘面配置 → 生成合法中奖结果 → 验奖 → 提取必要元素
→ 按原始最终倍率分桶 → 重放验证 → 保存候选骨架与清单
```

- 骨架只固定决定中奖所需的图标、奖励数值、位置或必要阶段。多阶段玩法保留重建所需的状态变化，不把包含余额、投注金额及随机装饰的完整付费局快照作为骨架格式。
- 相同倍率可保留多条不同骨架。1 倍桶有 100 条、5 倍桶有 1000 条，不代表这两个倍率的开奖概率为 1:10；桶内数量不能成为倍率权重。
- 随机采样、定向构造或穷举均可用于覆盖倍率；生成频率、补齐次数、去重和容量裁剪均不改变数值页的中奖率和倍率权重。
- 逐条验证骨架能按实际规则重建，必要固定元素参与计奖，最终原始倍率精确等于桶键。处理小数倍率时沿用精确十进制或整数缩放口径，避免浮点尾数产生错桶。
- 对照对应模式倍率表，显示正权重正倍率的覆盖数和缺失列表。缺失倍率应报告，不能自动删除该档、调整权重、借用邻近倍率或回退成空奖。
- 不可达倍率需报告规则和证据，不能因为生成不出就自动改变数值配置。只有任务明确包含调表时才调整，并给出对均值和 RTP 的影响。
- 保留既有分块工作线程、进度、固定种子、停止保留完整结果及容量限制的能力。配置变化后不能将旧结果伪装成新配置生成的结果。
- 骨架库与元数据分开保存，沿用各玩法已有格式。保存时按配置版本重验，创建独立候选批次，不自动启用或覆盖旧批次。

## 后端实玩契约：空奖实时生成

每个开奖单元遵守：

```text
按配置判断中奖
├─ 空奖：实时生成符合该玩法的合法空奖结果
└─ 中奖：按倍率权重表抽倍率 → 选取对应倍率骨架
         → 实时补齐非中奖位置 → 验证奖金一致
```

- 模式选择、特殊功能触发及多转组合按该游戏规则执行；不能让骨架是否存在或生成成功率改变触发率、中奖率和倍率分布。
- 空奖不依赖预存零倍率桶，不把生成空奖库设为新玩法上线前提。已有历史零桶不属于清理授权，不顺手删除。
- 实时补空保留骨架固定元素及必要阶段，不新增中奖线、中奖格、中奖方式或奖励奖金，不改变最终倍率。
- 对单转之外的奖励、累计奖金和封顶使用明确的结算口径；累计奖金不等于累计盘面符号。
- 工具预览和重放同样遵守奖金不变的补空约束，不能把随意填满后的盘面当作该倍率的合法结果。

## 开发计划与代码定位

开始修改前，明确本次涉及数值输入、理论模型、模拟、验奖、骨架、保存中的哪些部分，并检查现有实现：

- 数值与配置：`slot_math/src/domain/model.ts`、`settings.ts`、`simulation.ts`，以及 `src/components/WeightTableEditor.tsx`。
- 页面与游戏共享状态：`src/App.tsx`、`src/components/DeveloperPage.tsx`、`src/state/GameWorkspace.tsx`。
- 参考 AG4 的职责划分：`src/components/paylines/RespinAnalysis.tsx`、`src/domain/fortuneTiger.ts`、`tigerSkeleton.ts`、`src/workers/tigerSkeleton.worker.ts`、`src/components/paylines/TigerSkeletonPanel.tsx`。
- 文件服务与候选库：`src/services/gameFiles.ts`、`server/game-files.mjs`、`server/tiger-library.mjs`、`server/board-library.mjs`、`vite.config.ts`。
- 当前规则及数据：`slot_math/README.md`、`game_configs/<游戏>/`、相关 `tests/`。

路径相对 `aislots` 仓库根目录；本节省略 `slot_math/` 的代码路径均位于该目录内。AG4 是架构参考，不是新游戏玩法模板。

- 新玩法计划至少交代：倍率表每档代表什么、中奖率和触发率的作用、总 RTP 组合方式、开发页生成的骨架单元、倍率覆盖及实时空奖/补空约束。不要擅自确定尚未确认的特殊玩法表口径。
- 参考 Lua 或其他项目时提取玩法、赔付、盘面及生成规则；不自动导入其结果表、概率或调控器配置作为新游戏数值，不以外部调控替代本工具的参数模型。
- 沿用项目文件读取、草稿、应用/保存语义、未保存提示及版本冲突检查。新增模式的配置与快照处理须明确，不用浏览器旧数据或隐式默认值填补业务配置。
- 数值工具任务不自动包含游戏服、客户端或部署改造；可以说明所需的消费契约，在明确的任务范围内实现。

## 验证重点

按改动选择有实际意义的验证，重点保证：

- 理论和模拟使用相同的中奖率、倍率权重、单位、功能组合和封顶规则；固定种子可复现。
- 骨架裁剪和重放不改倍率，补空不新增中奖；空奖重验为零奖。
- 同一配置下，改变每倍率保留条数或生成批次不会改变配置决定的奖金分布和理论 RTP。
- 缺失倍率、配置过期和保存冲突显式报错；配置与库保存不互相覆盖，候选不自动启用。

涉及代码改动时，在 `slot_math` 下使用 Node.js 22.12 及以上版本运行相关测试；交付前执行 `npm test` 和 `npm run build`。仅编写本技能时验证技能文件即可。
