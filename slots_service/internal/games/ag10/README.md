# AG10 金兔服务端

`fortune_rabbit_v1` 是 AG10 的独立游戏模块。普通转和特殊转先按各自中奖率判断，再从对应倍率权重表选原始倍率，最后从该倍率桶取一条已验证骨架。骨架条数只影响盘面形态，不改变倍率概率。

AG10 按 Lua 1022 的赔率和概率表接入：三列 3、4、3 格、十条中奖线，百搭只替代普通图标；普通奖金结算后独立判断是否追加 8 次特殊转。特殊转每转清空，至少 5 个奖励符号才支付该转奖励之和；普通线奖与特殊奖励都结算，整局封顶 5,000 倍。空奖由服务端实时生成，补齐只进行一次且不会新增中奖。

## 配置与本地发布

数值输入见 `game_configs/AG10`。`config.json` 使用 Lua 1022 的普通中奖率 0.29、当前特殊单转中奖率 0.34、触发率 0.006、8 次特殊转和 5,000 倍封顶；`paylines.json` 的图标赔付也以 Lua 1022 为准。

在 `slots_service` 目录生成新的不可变本地发布：

```sh
go run ./cmd/ag10-publish \
  -config ../game_configs/AG10 \
  -base ../game_libraries/AG10/base/<候选版本> \
  -free ../game_libraries/AG10/free/<候选版本> \
  -out testdata/deployments/2026-11-16-ag10/AG10
```

发布命令会用 AG10 当前四份配置重新验奖、验补齐和正权重倍率覆盖，生成独立的配置哈希与 manifest；目标目录已存在时拒绝覆盖。服务启动还会再次核对这些哈希和每条骨架。

## 骨架和空奖

`fill.go` 与数值工具的 `fortuneRabbit.ts` 使用相同的一次补齐规则：保留骨架固定格，按格过滤会形成新中奖线的普通图标后抽取一次；没有重摇、回溯、替换倍率或替换骨架。特殊中奖骨架的空位保持空白，普通中奖骨架由后端补齐普通图标。

空奖先按二项分布 `Binomial(4, 0.4)` 决定奖励符号数量，再在十格中无放回抽位置并按奖励面值权重生成；普通转的其余格用同一约束补齐，特殊转的其余格保持空白。空奖最多 4 个奖励符号，因此不会达到 5 个，不会产生额外奖金。

## 结算和验证

一次付费流程保存普通转及最多 8 次特殊转的逐帧结果。第一帧扣投注，后续帧消费已保存结果并立即支付当转奖金；封顶时只支付剩余额度并停止后续转。重试、恢复和回放读取已保存帧，不重新生成随机数。

```sh
go test ./...
go vet ./...
```

服务端测试覆盖配置哈希、骨架覆盖、一次补齐、空奖不中奖、逐转派奖、封顶和状态恢复。
