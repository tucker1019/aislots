# AG4 Fortune Tiger 客户端移植计划

本轮只调查和编写计划。实施目标是在 `client/fortunetiger` 创建独立的 Cocos Creator 3.8.5 工程，保留 Fortune Tiger 的美术与表现，接入本仓库 AG4 Go 游戏服务。源目录 `/Users/zhaoyao/cocosProject/games/fortunetiger_1017-master` 保持只读；不覆盖现有 Go、大厅或其他机台改动，不发布远程环境。

## 1. 先完成工程导入和无网预览

- [ ] 确认目标路径不存在，记录源资产清单；从源工程复制 `assets/` 和配套的 `.meta`，只带必要的项目设置和可用预览模板。保留资产 UUID、bundle 名及场景引用，项目名和项目 UUID 单独设置。排除 `library/`、`temp/`、`build/`、`local/`、`release/`、`hot_update/`、旧构建日志和上传脚本，不照搬旧 package 脚本或 Android 配置。
- [ ] 源项目是 Creator 3.6.3，已核实本机 `/Applications/Cocos/Creator/3.8.5/CocosCreator.app` 的版本为 3.8.5。仅打开目标副本，由编辑器重新导入并写入升级后的设置。检查场景、Prefab、动画、Spine、字体、声音及动态资源路径，排查缺失脚本、UUID 和错误引用后再开始接口改造。
- [ ] 从 `assets/h5main.scene` → `main.ts` → bundle `szcw_1017fortunetiger` → `game.scene` 核对实际入口及 `FTGameScene.scene` 依赖。替换 `main.ts` 中原平台强依赖，给加载失败加重试；保留游戏场景与原动画组件。编辑器预览可用显式开发 fixture 进入，显示开始按钮及本地资源加载状态；固定样本与真实 HTTP 入口隔离，生产构建不能启动 fixture 或旧试玩开奖。

## 2. 接入身份、投注和逐帧会话

- [ ] 在 AG4 bundle 内增设独立 HTTP 层、帧校验器和回合控制器。参考 AG3 的 `LaunchSession`，使用大厅 `launchTicket` + `exchangeId` 换 AG4 游戏令牌；沿用 AG4 独立会话、清理地址栏票据、父页面退出消息的约定。无票据且无会话时提示从大厅进入。本地联调可选已配置的测试登录，不内嵌默认付费身份。生产走同源 `/api/v1`。
- [ ] 收口原链路：`FTLogin` 的 WebSocket 登录/进房/ready、`FTGameLayerCtrl.initNetRespone/onMessageOpenAward`、`FTOptCtrl → FTSendManager.sendGo`、旧钱包/退出 `FTPlatformMgr` 和 `GameBridge`。新控制器给画面组件传入**单帧**数据；禁止把多轮拼成旧协议的 `mRotateData/mFreeList` 再自动播放、沿用本地试玩结果或连接源厂商。先断开入口，再删除无引用的旧模块；逐个核对场景脚本 UUID 后才能删带组件的脚本。
- [ ] 登录后读取 `GET /games/AG4/bets` 和 `GET /games/AG4/state`（均在 `/api/v1` 下，Bearer）。以 HTTP 实现为准：`betOptions/defaultBet` 是整数分字符串，`betLevel` 是上限，`lineCount=5`；用服务端 `amountScale` 格式化，金额计算在整数分进行。投注列表把基础档×等级（1 至上限）×线数排序去重，保留每档原始参数。付费旋转前若余额不足，显示提示，不转轴、不发 spin；恢复与续转不做新下注的余额校验。
- [ ] `POST /games/AG4/spin` 发送 `{requestId, bet: "10", betLevel: 1}`，例中总额为 50 分。实时帧/状态金额按 Go HTTP 实际的 JSON 数字读取，校验安全整数；历史摘要等字符串分字段独立解析，精确倍率/分数保留原字符串。不要依据文档总述把实时金额都当字符串。请求单飞，成功且帧校验通过才推进到 `nextRequestId`；`continue` 在当前帧表现完后发下一次，`complete` 后才能开始下一笔，不发送 betId 或动画确认。
- [ ] 超时/掉线/5xx 使用 AG2 的每次 10 秒超时和 2、4、6、8、16 秒退避；AG3 的 15 秒实现不直接照搬。整个重试链冻结同一份请求体，耗尽后提示重试同一请求；明确业务错误走相应提示/会话恢复，不盲重试。请求结果未明时锁定新下注与调档，迟到或重复响应只呈现一次。离开场景取消计时和本地请求，不据此推断服务端回滚。
- [ ] 重进用 state 顶层 requestId、balance 和 lastFrame 静态恢复；`hasNext=false` 留在原盘面等待手动下注；`hasNext=true` 仅续转。当前 Go state 只提供整局总额，没有原始基础档和等级；同一页面保留原组合，跨刷新按**精确总额**从当前配置找等价组合（HTTP 会先换算总额再传给服务层），禁止默认选另一金额。若找不到、或接口联调验证等价组合不受支持，停止续转并显示可恢复错误；在开放大厅入口前与服务端对齐返回原组合或提供独立续转方式。

## 3. 按服务端帧驱动原表现

- [ ] `FTConstant` 的 `c0` 是空格；`c1～c7` 依次是橘子、鞭炮、红包、福袋、如意、金元宝、Wild，与 `game_configs/AG4/paylines.json` 一致。按 `board[col][row]` 渲染：从左到右列为 `1/2/3`、`4/5/6`、`7/8/9`，列内从上到下；以格 ID 对齐 `FTCellLayer` 和中奖线，首个 fixture 用不对称盘面排除转置。AG4 没有预览行、底部装饰格、消除或 `start_free`。无效盘面报错，随机只可用于尚未揭晓的模糊滚动和装饰动画。
- [ ] 普通局：`FTCenterRollCtrl` 收到合法帧才允许停轴；用服务端盘面落点和中奖线表现。等待期间点 Stop 或点棋盘只记录加速意图，结果到了才停；点击不发第二次请求，也不跳过任何结算帧。明确拒绝可退出等待并回到上次已确认的画面，不展示伪结果。
- [ ] 重转：首帧空盘展示 `targetSymbolId`，复用红包/飞入/背景特效，拆开旧 `triFreeGameAnim` 对整份 `mFreeList` 的依赖。每帧 `lockedCellIds` 是当前全部锁位，包含本帧新增；保持旧锁位不转，只播放 `addedCellIds` 新落位（首帧列表可能为 null，按空列表读取）。无新增或填满由服务端结束，客户端只认 `nextAction`。恢复时用 lastFrame 的完整锁位直接显示，不重放开场或提前展示未来格。
- [ ] 最终帧按 `gameData.lineWins` 的 0 起始 `lineIndex`、`cellIds`、`symbolId` 显示中奖线，按 `bonusMultiplier` 显示全屏倍数；金额用已结算的 `winAmount/totalWinAmount/balance`，不从线赔率重算。旧 `onMessageOpenAward` 的本地减款、钱包推送覆盖移除。首帧表现一次扣款；重转中间帧不加赢分，末帧在赢分表现完成时同步到服务端余额。续转或重播不重复加钱，回放不写当前钱包。
- [ ] 复用 `FTBonusAniCtr/FTBigWinCtrl/FTAudioMgr`。Big Win 点击先快进计数，再按原按钮关闭；跳过、正常关闭和离场统一收尾，清理计数 tween、金币和烟花循环音及 Big Win 音乐，仍在游戏内才恢复对应 BGM；静音时不得被回调重新开启。关闭特效不触发下一笔下注。自动投注沿用同一结算/余额门控，一整局未完不启动下一笔。

## 4. 恢复、回放和大厅本地联调

- [ ] 历史列表和私人回放走 `/games/AG4/bet-records` 及 `/{betId}/replay`，公开回放走 `/games/AG4/shared-replays/{betId}`；沿用分页 `nextCursor`、`?replay=&share=` 和 share 接口。AG3 历史网络及只读播放可借鉴，AG4 的帧解析和画面仍走本机台渲染器，保留 `gameData`。仅播已返回的帧；公开回放不登录、不请求 bets/state/spin、隐藏余额和下注入口。

## 5. 验收与交付

- [ ] 建立最小确定性测试：普通输/赢、重转首空帧、累计锁位、无新增结束、填满 ×10、非法格、金额单位与去重、余额不足零请求。加入 Go 真实返回样本，核对同一 betId 每轮实玩/state/私人及公开回放的盘面、锁位、中奖线和赢分一致。校验只首帧扣款、只末帧派奖。
- [ ] 模拟响应在结算后丢失，确认原请求幂等、连点不推进两轮、超时仍不停到假盘；分别在首帧、重转中途、末帧刷新，核对恢复、下一请求和钱包。用可控慢网检查 Stop/点棋盘、Big Win 跳过与音频清理；检查公开回放没有登录和 spin 请求。
- [ ] 用 Creator 3.8.5 做编辑器预览及干净的 Web Mobile 构建；仿 AG3 写本地构建命令，保留 build log，确认构建任务完成并生成新的 `build/web-mobile/index.html`。静态托管产物，从大厅实际进入验证票据、音频、竖屏适配、历史和退出。记录版本、命令与验收结果后再报告完成；不把旧产物或可打开编辑器当成构建通过。
