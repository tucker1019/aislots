# 好友桌：需求与资金规则

状态：设计草案，尚未实施。入口见 [评审包](README.md)。金额示例使用金币；存储与结算沿用现有最小货币单位整数，禁止浮点计算。

## 目标与范围

让 2–4 位好友以相同游戏、相同 Bet 和相同付费局数进行对战，实时观看彼此 Spin，以总派彩定胜负。桌子在服务端持续运行，不依赖任意玩家保持页面在线。

本阶段规划开桌、邀请、一次扣款、准备／开始、实时对战、离线继续、奖池结算、记录、独立报表和活动隔离。好友关系系统、聊天、公开匹配、观众、排行赛、赛事抽水、专属奖励的实际条件与金额不在已确认范围；不为这些功能预设收费或发奖。

## 已确认业务规则

| 项目 | 规则 |
| --- | --- |
| 人数 | 2–4 人；建议建桌时固定目标人数，不在入桌后悄悄改变 |
| 游戏与参数 | 同桌同一游戏、每局实际投注 B、局数 N、每人对战赌注 S |
| 赌注上限 | `0 ≤ S ≤ B × N`；是否允许零赌注桌尚待确认 |
| 入桌扣款 | 房主创建成功、其他人确认入桌成功时，各自一次性扣 `S + B × N` |
| 开局后 | 参数不可改，不能取消参赛或取回押注；离开页面由系统继续 Spin |
| 游戏本金 | 预付，仅消费本桌本金；N 局内不再扣可用钱包余额 |
| 正常派彩 | 每位玩家自己的游戏派彩归自己，不进入对战奖池 |
| 成绩 | N 局的总游戏派彩；不包含奖池收入、退款或额外活动奖励 |
| 奖池 | 参赛人数 × S；唯一最高者获得全池，无已确认的平台抽水 |
| 平局 | 两人平局各退赌注；3–4 人部分并列最高的分配规则待定 |
| 活动 | 本桌投注、派彩、对战奖池和专属奖励不得污染普通活动统计 |
| 报表 | 个人报表单独提供“好友桌”，保留原有时间筛选 |

同 Bet、同 N 是比赛公平条件；**不表示开奖结果相同**。不得为了造平局或触发奖励改动 RNG、RTP 或正常派彩规则。

## 局数与游戏边界

**建议口径，需在接首款游戏时确认：** 一局指一次付费投注及其完整派生过程。消除帧、重转、自动免费旋转均归属该次付费投注，不额外计入 N、不额外消耗 B。

- 只有该付费链的全部派彩已可信结算、完成事件已确认，才增加 completedPaidSpins。
- 触发免费游戏后必须执行到该链结束，不能在第 N 次付费点击后截断免费派彩。
- 禁用购买免费游戏、加倍投注、改 Bet、无限自动旋转等与固定 B/N 不相容的入口；不能把“下注面板输入值”直接当实际 B。
- 游戏若有额外付费购买或跨局持久特征，须逐游戏明确兼容方式后才开放。
- 派彩可逐帧到账，但一局最终成绩以完整付费链为准；不重复叠加完成事件与逐帧派彩。

## 资金模型与算例

一次入桌的对外资金动作是一个不可分割的扣款事务：

```text
预付游戏本金 P = B × N
入桌总扣款 E = S + P
房间奖池 Q = 实际已入桌人数 × S
```

钱包只减少 E 一次；后台内部同时记录 S 和 P 的去向。每次付费 Spin 从本桌剩余 P 扣 B，不能再从钱包扣 B。每帧中奖加到本人钱包，并独立记录好友桌来源。

以两人 `B=10、N=20、S=100` 为例：

| 阶段 | A | B | 房间资金 |
| --- | ---: | ---: | --- |
| 入桌 | 钱包 −300 | 钱包 −300 | 奖池200；A/B预付本金各200 |
| 完成20局 | 本金消耗200，游戏派彩180 | 本金消耗200，游戏派彩260 | 未用本金0；待分配奖池200 |
| 唯一赢家结算 | 奖池收入0 | 奖池收入200 | 奖池余额0 |
| 最终钱包净变化 | −300+180=−120 | −300+260+200=+160 | 两人净变化合计+40，等于游戏派彩440−实际投注400 |

游戏派彩180/260属于各自正常收益；奖池是另外的对战输赢。没有任何“再扣100赌注”或“结算再扣200投注”的步骤。

### 撤销与异常退款

- **开局前建议**：主动退出、房主取消、等人超时均退还本次 S 与未消耗的 P，全额原路退回，不产生实际投注。
- 开始与退出并发时只能有一方成功；若开始事务先提交，退出只能变为“离开页面，系统继续”。
- **开局后正常掉线**：不退款，系统继续。已付本金足够 N 局，不向钱包追加扣款。
- **系统故障**：先暂停恢复；不能因超时重抽开奖结果、判离线玩家输，或直接全额退已消费本金。
- 若确实无法恢复，异常中止与补偿政策必须另行确认：建议不追回已确认派彩，只退未消费本金和未分配赌注；已消费局数不伪装成撤销。该建议未经确认不能自动执行。

## 活动排除矩阵

在可信结算和记账端使用 `scene=friend_table` 及 roomId；客户端不能指定/更改该身份。真实账号仍是 real，不能借用 experience 账号类别来排除活动。

| 下游 | 好友桌处理 |
| --- | --- |
| 日／周／月反水 | 不增加普通有效投注，不产生普通反水 |
| 亏损返还 | 好友桌投注／派彩均不进入普通净亏损；好友桌专属奖励与奖池收入也不能被“赠币来源”误选进去 |
| 签到 | 不增加普通活动的投注、充值金额或次数 |
| VIP | 不增加升级／保级／周月礼金的投注达标进度；好友桌入桌扣款、退款不是充值 |
| 代理佣金 | 不生成佣金投注贡献、厂商档位进度或队列任务 |
| 邀请／新手 | 不增加普通任务的投注、充值或邀请达标条件；不改变已有邀请关系 |
| 新增普通活动 | 未明确允许好友桌之前默认排除；接入清单必须包含好友桌隔离用例 |
| 个人记录／运营审计 | 保留完整真实交易，好友桌单独归类，不因排除活动而丢失资金记录 |
| 提现所需流水 | **待定且独立**：不能把普通活动排除等同于免提现限制，见 D04 |
| 公共游戏榜／RTP统计 | 建议独立分场景，默认不混入公开普通榜；不是已确认需求 |

规则覆盖所有好友桌来源：入桌预扣、内部本金消费、游戏派彩、奖池支付、退回和未来专属奖励。只把有效投注设0不够：普通亏损返还直接读取实际投注和派彩，仍会被污染。

## 个人报表

个人报表增加业务选项“普通游戏 / 好友桌”，好友桌沿用今天、昨天、本周、上周和服务端活动时区。充值／取款是账户级数据，不虚构分摊给某一桌；好友桌分区展示本场景指标。

| 好友桌指标 | 口径 |
| --- | --- |
| 实际投注 | 已执行付费 Spin 消耗的本金；入桌预扣不算实际投注 |
| 游戏派彩 | 本场景已确认游戏 credit；免费／消除计入其原付费链 |
| 游戏输赢 | 游戏派彩 − 实际投注 |
| 对战押注 | 当期实际进入奖池的 S，显示正数支出 |
| 押注退回 | 平局／开局前取消等实际退回的原押注 |
| 奖池奖金 | 胜出实际取得的整份奖池，含赢家原押注部分，不再重复记作“押注退回” |
| 对战输赢 | 奖池奖金 + 押注退回 − 对战押注 |
| 专属奖励 | 好友桌专属规则实际到账金额 |
| 好友桌净输赢 | 游戏输赢 + 对战输赢 + 专属奖励；不含预付本金扣除／本金退回 |
| 资金明细 | 另展示入桌预扣、未用本金退回、钱包变化，便于与钱包逐笔对账 |

比赛成绩按桌累计完整付费链；报表按真实发生/到账时间统计。跨日时某一天可能只看到押注或派彩的一部分，必须能跳到单桌完整对账。非终态桌标注“进行中／暂停中”，不能用当日报表推断最终赢家。

## 未来专属奖励

只预留扩展结构，不启用真实奖励、不臆定金额。例“2人、各完成N局、总派彩完全相等、每人至少中奖一次”还需要明确：

- “一样”是总派彩精确到最小货币单位相同，还是净输赢／排名相同？
- “中过奖”是任意单局派彩>0，还是单局盈利，免费过程中中奖算不算？
- 每人发固定额还是按Bet比例、每天几次、同一对好友能否反复触发？

未来规则以稳定ID和版本快照保存；开桌绑定版本，完成后生成事实快照，按 `(roomId, uid, ruleVersion)` 幂等评估和入账。规则变更不重算已结算桌，默认关闭，奖励与本金、奖池分别核算。

## 待定事项

| ID | 事项 | 建议 | 影响／阻断范围 |
| --- | --- | --- | --- |
| D01 | 3–4人部分并列最高 | 并列者平分全池；余数按固定席位顺序分配，全员同分各退S | 确认前不开放3–4人真实奖池结算 |
| D02 | 精确目标人数与开始方式 | 开桌选2/3/4人；满员且全员准备后房主点击开始 | 房间和页面交互 |
| D03 | 等人超时、房主离开、零赌注桌 | 等人10分钟全退；房主开局前退出则取消；是否允许S=0待定 | 参数只作建议，不先写死业务配置 |
| D04 | 提现流水 | 好友桌投注是否抵扣既有提现要求、专属奖励增加几倍流水分别配置；本金退回保留原性质，不增加／清除既有要求 | 真实资金上线阻断项 |
| D05 | 不可恢复故障补偿 | 暂停优先；审批后退未消费本金与未分配赌注 | 自动中止策略、运营审批与审计 |

| D07 | 首发游戏、N范围、档位、节奏 | 一款验证游戏；固定档位，服务器按节奏推进；在线时是否保留手动 Spin 按钮待定 | 游戏适配和性能验收 |
| D08 | 房间邀请方式与并发参赛限制 | 私密邀请码／站内链接；首版每账号最多一桌，参赛时禁止发起普通Spin | 防冲突，不预设必须先做好友关系系统 |
