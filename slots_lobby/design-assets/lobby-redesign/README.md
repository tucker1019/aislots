# 大厅改版提案

这份提案根据当前 `src/pages`、`src/features` 和服务接口组织页面，保留现有墨绿与暖金主题。`unslop` 用于检查表达是否明确，不用它替代 UI 规范。

## 查看预览

在 `slots_lobby` 启动静态服务器：

```sh
python3 -m http.server 4178 --bind 127.0.0.1
```

打开 <http://127.0.0.1:4178/design-assets/lobby-redesign/>。预览使用本地字体、头像、Banner 和游戏封面，没有外部资源或运行依赖。全部金额、日期、进度、领取状态和订单都是设计示例，不读取账号数据，不请求业务接口。`games.json` 从仓库目录提取封面及名称，仅作排版样本，正式页面仍以目录接口的排序、可见和启用状态为准。

## 页面与功能

| 页面 | 设计调整 | 继续沿用的业务 |
| --- | --- | --- |
| 首页 | 紧凑资料栏；通知和 Banner 保留；签到、VIP、反水作轻量入口；厂商筛选下方保持三列封面 | 动态目录、未开放提示、分批加载、真实封面、图片骨架流光 |
| 存款 | 余额、档位、明细、提交依次排列；总到账金额独立强调；赠送与手续费用明确文字区分 | 服务端档位、金额单位、幂等订单、付款页面、轮询、历史订单及状态 |
| 取款 | 金额、手续费、到账、渠道和账户明确分行；提交前展示确认信息 | 限额、校验、钱包要求、幂等及订单状态；预览仅列出范围 |
| 赚钱 | 反水与亏损返还分别成卡；可领金额与下一期预估分区；代理佣金和邀请奖励有独立入口 | 日／周／月来源、领取窗口、反水合领、亏损返还单独领取；不把预估金额加入可领金额 |
| 福利 | 七天签到显示当前天与两项任务；周／月礼金显示所属结算周期、条件及领取状态 | 中断重置、手动领取、新手累计多档叠加、注册起算期限；新手活动预览仅列出范围 |
| VIP | 当前等级、当级进度、可领取升级奖励、周／月工资分开；保级任务独立显示 | 每级独立门槛；工资按结算等级；历史最高等级防重复奖励；保级开始清当级流水，成功计入、失败降级清零；任务快照不随配置改变 |
| 我的 | 身份与钱包在上；福利、记录、账户服务按用途分组；主操作只强调存款 | 头像编辑、语言、钱包管理、报表、安全及退出；不隐藏现有功能 |
| 代理／邀请 | 保留团队、业绩、佣金明细和邀请奖励的独立页面，入口从赚钱／我的可达 | 绑定关系、日结、厂商规则、手动领取和经验账号标记；预览仅列出范围 |
| 记录 | 时间与金额按行对齐；状态用文字加语义颜色；列表到详情层级一致 | 存取款订单、钱包账变、投注记录、个人报表、筛选及游标分页 |
| 游戏／回放 | 大厅只统一标题、榜单与分享面板；实际机台保留原生 Cocos 画面 | iframe 复用与收起、音效桥、登录入口、原版动画、分段推进、上一结果→旋转→本次结果、回放余额遮罩；不将样本榜单接入正式数据 |

预览中完整绘制首页、存款、赚钱、我的、福利、VIP、交易／投注记录及游戏外壳。取款、代理、邀请、报表、安全等只有范围说明，不算已完成的页面设计。交易详情、保级说明和回放说明可通过弹窗查看；预览不播放真实机台。

## 颜色与排版

- 画布 `#102C2B`，面板 `#193A36`，次级区域 `#264C45`，分隔线 `#35564E`。
- 主文字 `#FAF6EB`，辅助文字 `#B2C6BC`，主操作／选中项 `#E9C88D` 配墨绿文字。背景不铺大面积金色，不给所有快捷入口加实心金底。
- 金额使用本地 Nunito、等宽数字；正文 12–14px，区块标题 16–18px，主要金额 24–30px。繁体中文继续使用 Huninn。长金额换行或调整容器，不能截断。
- 卡片 14px 圆角，按钮 10–12px，图标统一线宽。不添加厚底座、装饰发光和滚动跑马金额。
- 固定四项底栏：首页、存款、赚钱、我的。其他详情页按当前路由规则隐藏底栏。420px 设计宽度，小屏整体等比缩放。

## 文案与状态

以印尼语为默认展示语言，同时保留繁体中文和英语。文案写明动作、金额、来源周期与状态，不使用未经验证的收益承诺。金额仍以整数分传输，统一公共 `Rp` 格式化，显示小数向零截断；预览仅使用已经换算好的示例元金额。

“可以领取”“未达条件”“已经领取”“已经过期”“等待结算”分别显示，不能只靠颜色。只有达到领取条件才出现可领标记。周／月工资必须显示上一周期的充值、投注条件和结算结果。新手奖励显示到期时间与每档领取状态。

保留已有小机台 777 loading；静态入口立即显示，只在真实接口字段位置局部占位。保留 Banner／封面骨架流光。操作请求按钮保持尺寸、显示居中旋转圈并防重复；首次加载失败用 NetworkError，已有内容刷新失败及操作失败用公共 Toast。Toast 不挡页面点击，不把错误插进卡片影响布局。

## 正式实施文件与数据流

方案确认后按页面实施，先统一公共组件，再修改业务页面：

1. `src/app/theme.ts`、`src/styles/theme.css`、`DESIGN.md`：确定最终颜色、字号、间距、按钮和状态规范，保留现有主题策略。
2. `src/components/Header.tsx`、`BottomNavigation.tsx`、`buttons/`、`feedback/`、`records/`：复用固定导航、按钮、Toast、加载及记录布局。
3. `src/features/home/`、`src/pages/DepositPage.tsx`、`src/features/deposit/`：首页与存款页，继续使用现有目录、档位、订单查询及幂等提交。
4. `src/pages/EarnPage.tsx`、`src/features/earn/`、`src/features/benefits/`、`src/features/vip/`：奖励来源、预估、条件与状态。复用 RebateForecast，不按列独立堆表。
5. `src/features/account/`、`src/pages/*RecordsPage.tsx`、代理／邀请／安全相关页面：账户入口、记录及其他业务页。
6. `src/i18n/` 和对应页面测试：语义 key、三语换行与状态回归。

服务仍由 `src/services` 请求，经 TanStack Query 管理服务端状态，再由现有业务组件展示。页面不直接 fetch，不改变奖励计算、付款流程、接口协议或 Cocos 客户端。领取／提交成功按原逻辑更新查询缓存和余额；展示层不能自行推算最终到账或可领取资格。

## 验收

正式实施后运行项目 lint、typecheck、测试及生产构建。浏览器覆盖三语、320px、小屏长文案、大金额、请求中、失败重试、无数据、未达条件和已领取状态；验证底栏、Toast、弹窗及游戏收起展开，不重挂 iframe。预览的浏览器检查不能替代正式应用验收。

本次预览检查（2026-11-20）：Playwright 使用本机 Chrome，检查八个主视图、存款选择及到账明细、弹窗开关、演示领取状态、图片请求和 320px 横向溢出，均通过。项目最终 lint、typecheck、205 项测试及生产构建通过；构建仍提示部分 chunk 超过 500kB。仅增加独立设计文件，未替换正式页面。文案扫描器识别为非英语，英文可读性及结构指标不适合用来验收中文设计说明，未将其软提示当作文案缺陷或宣称全项通过。
