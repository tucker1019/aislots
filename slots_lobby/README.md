# AISlots 游戏大厅

独立 React + TypeScript 前端，位于仓库根目录 `slots_lobby/`。使用 Ant Design、TanStack Query、Zustand。

## 运行

需要 Node.js >= 22.12，推荐使用仓库当前的 Node 22.22.2。

```sh
cd slots_lobby
npm ci
npm run dev
```

打开 http://127.0.0.1:5175/ 。构建预览运行 `npm run build`、`npm run preview`（4175端口）。

## 页面适配

大厅最大宽度430px，电脑上居中、两侧留灰底，手机上铺满可用宽度，不使用整页缩放。顶栏下依次为通知、Banner、厂商分类、三列游戏网格；当前只有麻将胡了一款游戏。旧搜索、收藏、最近玩过、底部导航及说明弹窗不再提供。

顶栏固定在顶部并预留等高内容空间，右侧显示真实金币与头像，兼容顶部安全区。

厂商入口只有“热门、AG、PG、JILI、PP”。热门和AG显示麻将游戏；其他厂商点击Toast“敬请期待”，保持当前分类与列表。通知及Banner目前为本地内容，通知在`src/features/home/content.ts`修改，Banner/封面资源位于`public/assets/lobby`，复制自现有麻将客户端。入口接口由并行接入任务实现，本次页面验收不包含真实下注或钱包结算。

## 大厅用户服务

先在另一个终端启动独立大厅服务（不替换8080端口的麻将服务）：

```sh
cd ../lobby_service
docker compose up -d
export LOBBY_DATABASE_URL='postgres://lobby:lobby-local-only@127.0.0.1:55433/aislots_lobby?sslmode=disable'
make run
```

开发和构建预览将 `/api/user` 代理到本机8081端口。正式部署需要同源反向代理，或者通过 `VITE_LOBBY_API_URL` 设置允许跨域的大厅接口源站；该变量不附加 `/api` 路径。

首次进入创建游客，本机身份保存后刷新先续期，再获取资料。会话失效保留原身份并提示错误，后续账号登录界面另做。Query持有资料及余额，窗口重新获得焦点且缓存过期时刷新；Zustand只持久化uid/sid/到期时间，密码和余额不落本机缓存。网络请求12秒超时，失败显示重试，不用0冒充失败结果。并发挂载共用一次登录，请求失败不自动重放创建游客。

余额为整数分，显示两位小数；服务端头像编号1–15对应 `public/assets/profile/avatar` 的同名图片，资源复制自用户指定的AB3目录。失败/加载时用中性占位头像。

## 目录

- `src/app`：应用入口、主题和Query Provider。
- `src/pages`：大厅页面组合和Toast，不直接请求接口。
- `src/components`：固定顶栏、品牌和金币图标。
- `src/features/account`：余额、头像及加载/错误/重试状态。
- `src/features/home`：通知、Banner、厂商选择及游戏卡片。
- `src/services/account.ts`：登录、续期、资料请求与响应校验。
- `src/stores/session.ts`：持久化身份，不缓存余额。
- `src/styles`：全局适配与顶栏样式。

大厅与麻将服务的身份及钱包尚未互通；当前不包含账号注册、充值、活动等页面。配置示例见`.env.example`。


覆盖游客登录去重、续期、身份失效、网络重试、响应校验、金额换算、首页区块顺序、厂商切换/提示、单游戏列表和用户资料加载/错误/重试。

## 路由

首页路径`/`，我的路径`/my`。使用History API，支持直接访问、刷新保留和浏览器前进后退；我的页隐藏顶栏并移除顶部占位，仅保留固定底栏。正式静态部署需将`/my`等前端路径回退到`index.html`，API路径继续走服务端代理。

## 存款页

`/deposit`由底栏存款和我的页存款进入；无大厅顶栏。查询充值档位，展示本金、赠送、手续费及到账金额。创建订单使用requestId幂等；不确定失败时重试同一请求号，不允许换档位；sessionStorage按UID保存本次意图及订单号，刷新可恢复订单查询。待确认订单每秒查询，成功/失败停止；查询失败显示手动刷新。成功后重新读取当前余额，不用历史订单余额覆盖资料。

当前后端为测试支付，页面明确提示约3秒自动模拟到账，不需要真实支付。付款链接仅接受HTTP(S)且禁止内嵌身份。开发/预览代理`/api/recharge`至8081，正式部署也需配置代理。自动测试使用模拟接口，不执行真实充值。

## AG1真实游戏入口

麻将卡片点击后，使用当前大厅uid/sid请求 `POST /api/game/launch`，等待服务器返回临时launchUrl后，在大厅/game/AG1游戏页通过iframe加载；不再直接打开固定测试客户端地址。进入按钮加载期间禁用，失败提示并可重试。开发代理已包含 `/api/game`。后端及共享服务凭据配置见 [AG1接入文档](../lobby_service/docs/game-integration.md)。

游戏页提供返回大厅和重新进入，隐藏大厅顶栏及底部导航；刷新保留当前iframe入口，已兑换票据复用游戏会话，不重复兑换。返回大厅重新获取钱包余额。

## 存取记录

“我的 → 存取记录”读取当前用户真实充值订单，支持全部/存款，以及今天、昨天、近7天、近30天筛选；取款提示敬请期待。时间由服务端过滤，列表分页追加，点击行进入可刷新的订单详情并复制订单号。详情返回保留列表筛选、分页和滚动位置，离开页面刷新钱包缓存。失败或未确认订单不会伪装为已到账。

页面切换和筛选浮层使用轻量过渡，并尊重系统减少动态效果设置。

VIP查看详情：福利中心“VIP中心→查看详情”进入 `/vip`，按真实等级显示升级差额、等级权益与保级状态；可横向选择其他等级查看权益。右上角“VIP详情”进入 `/vip/details`，展示晋级/保级、礼金和周期条件三张完整配置表，高亮当前等级。数据来自 `/api/vip/info`，金额由分换算为元，本次功能仅查询展示。
