# 大厅运营后台

后台前端位于 `slots_lobby_admin`，服务端为独立入口 `app/apis/lobby/api/admin`。玩家服务和后台默认分别监听127.0.0.1:8081、127.0.0.1:8082；后台接口不会注册到玩家监听器。游戏后台未来独立开发，不连接或修改机台数据库。

## 本地运行

数据库沿用独立的 `aislots_lobby`。从 `lobby_service` 运行：

```sh
./script/admin.sh bootstrap
./script/admin.sh
```

初始化命令交互输入管理员名称和14至72字节密码，不回显密码，也不提供默认密码。只能新建账号，重名不会覆盖。脚本读取本地 `.env.local`，从而沿用开发数据库配置；不要将该文件或口令提交。

另一终端：

```sh
cd slots_lobby_admin
npm ci
npm run dev
```

前端 http://127.0.0.1:5176 。已有大厅进程需使用本次版本启动一次，之后后台配置发布无需重启。管理员权限与玩家uid/sid完全独立。

可选环境变量：`LOBBY_ADMIN_ADDRESS`（默认127.0.0.1:8082）、`LOBBY_ADMIN_ORIGINS`（默认两个本地5176入口，逗号分隔）、`LOBBY_ADMIN_COOKIE_SECURE`（HTTPS部署设true）。生产必须由同源HTTPS代理转发后台API，限制管理入口；不要公开开发服务器或数据库。未来部署另行配置，不会跟随本地开发自动上线。

## 权限与审核

角色：admin全部；operator查询/草稿/校验；finance查询/资金审核；viewer只读。角色和停用状态每次请求从数据库校验，前端隐藏按钮不是权限边界。会话有效期8小时，HttpOnly/SameSite严格Cookie，随机令牌仅存哈希；写入要求允许的Origin和自定义请求头，登录有限流。

- 存款确认：只按原pending订单金额入账，不能修改金额；退回关闭待付订单。支付模拟worker与审核共用钱包锁和订单状态判定。
- 取款通过：仅变成approved，表示审核通过、待付款；不伪造真实打款、不再加减本金。退回pending订单才退还原扣除本金。已审核订单不能重复退回。
- 所有审核需要理由、请求标识，审核记录和账变/订单/审计同一事务提交；重复请求不会重复入账。原测试取款模拟按钮仍按原测试语义工作。
- 会员和收款资料只读，账号/姓名脱敏；不提供任意修改余额的接口。

真实支付渠道/实际出款尚未接入，本后台不会模拟成外部已付款。已批准取款应在接入真实渠道后由独立付款状态流程完成。

## 配置生效边界

12个分区：公告与轮播、存款、取款、签到、反水与亏损返还、流水倍数、代理、VIP、邀请、新手充值、游戏入口、体验账号。部署密钥、数据库、端口、活动时区、平台身份/币种保留部署初始化边界；时区和平台身份的在线修改会被拒绝，不能移除已有VIP等级。

已有etc文件仅初始化数据库中缺失的分区；重启不会覆盖后台发布版本或草稿。编辑不生效，校验不生效；发布/回滚才生效。保存草稿使用当前 `max(publishedVersion,draftVersion)` 做并发校验；发布用draftVersion；回滚用publishedVersion。冲突必须重新读取，不能静默覆盖别人的发布。

每次发布与回滚保存版本、理由和审计。回滚创建新版本，不改写旧版本。业务配置的version由服务端生成唯一发布标识；新手注册时已保存的规则、已经创建的资金订单、已生成VIP奖励保留各自快照。签到规则版本改变会开始新签到连续周期。代理已开始统计的历史日继续沿用原规则快照。流水倍数只影响之后入账产生的流水要求。

反水费率从下个对应日/周/月周期开始，亏损返还按下一日。既有周期和已结束待领取周期保留原费率；同一尚未开始周期多次发布，以最后一次为准。后台配置显示待生效最新设置，大厅展示当前周期实际费率。回滚同样从下个周期开始。

大厅每2秒检查轻量发布版本；读取一致数据库快照、校验后原子切换新请求依赖并重启相关worker。处理中的请求保留原依赖；加载失败保留上一快照并写服务日志。没有轮询扫描历史投注记录。

公告与Banner支持繁体中文/英文，独立文案和图片URL。只允许站内 `/`、`/earn`、`/deposit`、`/offers` 跳转；图片使用 `/assets/` 或HTTPS CDN地址。文件上传和CDN自动刷新不在本期；先把资源放在现有静态目录或对象存储，再填写URL。消费者首页立即显示本地默认内容，然后请求公开的 `/api/lobby/content`；失败保留默认内容并提供局部重试。重新进入或刷新页面后读取发布内容。

## 可复现检查

使用Go1.25及Node22。后台协议和HTTP路由独立生成，`make build`生成全部玩家/后台协议，`make admin-build`仅生成后台；`make model`从已迁移的真实表生成模型。

```sh
GOTOOLCHAIN=local make build
GOTOOLCHAIN=local go test ./...
```

设置 `LOBBY_INTEGRATION_DATABASE_URL` 为独立 `aislots_lobby` 连接后，事务测试在随机临时schema运行并清理，覆盖并发、幂等、审核回滚、配置版本冲突/回滚和运行时热切换。没有对真实会员执行测试资金审核。
