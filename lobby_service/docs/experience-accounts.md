# 平台体验账号调度

后台「体验账号」使用数据库草稿与发布版本，每5秒调度时读取已发布配置。`etc/experience.json` 仅在分区首次初始化时提供配置，`LOBBY_EXPERIENCE_CONFIG` 可覆盖文件路径；修改文件不会覆盖数据库已发布内容。

```json
{"enabled":true,"initialCoinsMin":10000,"initialCoinsMax":1000000,"initialCoinsStep":10000,"betDivisorMin":100,"betDivisorMax":300,"createMinSeconds":30,"createMaxSeconds":120,"playMinSeconds":10,"playMaxSeconds":30}
```

- 每隔随机30～120秒创建一个新体验账号；持久化下一次创建时间，重启不补建历史间隔。
- 初始余额从 initialCoinsMin 到 initialCoinsMax 按 initialCoinsStep 等概率选取（单位分）；默认 Rp100～Rp10.000、步长 Rp100，资金来源exp_001，仅在创建事务注入一次。
- 初始余额除以 betDivisorMin～betDivisorMax 范围内随机整数（默认100～300），得到目标单局总投注，遍历游戏服返回的合法bet、betLevel、lineCount，选择总投注最接近的组合；距离相同选较小总投注。账号创建时固定档位，头像从现有1～15号头像随机选择并保存。
- 每局全部消除和免费结束后，随机等待10～30秒再开始；按5秒调度轮询，实际开始可有约5秒轮询延迟。
- 每完成50局检查一次20%概率永久停止，即50、100、150……局检查；免费局和消除轮不单独计局。
- 余额不足永久停止，不补币、不替换原账号。停止原因记录insufficient_funds或round_probability。其他网络/业务错误保留原命令恢复。
- stopped账号不再开新局，不影响继续创建账号；enabled=false停止创建和开新局，但排空已保存请求。

大厅先持久化requestId再调用机台。`POST /internal/auto-bets`读取合法投注配置；`POST /internal/auto-round`执行整局。两个接口都使用服务间Bearer，不对浏览器开放。待执行命令保存国家、币种、投注档位。机台每轮保存token，已结算轮按token读取原回执，防止中断后重复扣款、派彩。

`lobby_experience_accounts` 保存账号、固定档位、已完成局数、停止原因、下一局时间和原请求；`lobby_experience_schedule`保存下次创建时间。大厅调度与机台执行均使用数据库锁，避免多实例重复。

体验账号保留真实订单、钱包、逐轮结算和回放。体验事件进入独立事件表，不参与VIP、签到、反水、邀请、代理、取款流水要求。页面RTP合并真实用户与体验账号；真实用户分钟汇总和体验完局数据分开保存，查询时合并，已有体验局也会计入对应时间窗口。公开排行榜仍显示“平台体验账号”标签，不能与真实用户混淆。

游戏按后台 gameWeights 在已启用且具备服务地址的机台间分配，已有账号不随权重改变游戏。无活跃账号总量上限；关闭配置即可停止增长。不要用浏览器同时操作体验账号。变更游戏合法下注规则前应暂停调度并排空旧任务。

## 余额与投注配置边界

- 金额字段为整数分，100分=Rp1；要求余额下限大于0，上限不低于下限，步长为正，且上下限之差可被步长整除。金额最大为9007199254740991分，以兼容后台安全整数输入。
- 除数要求 `1 <= betDivisorMin <= betDivisorMax <= 1000000`。除数越小，目标投注越大；实际投注始终匹配游戏合法档位，并非直接使用任意金额。
- 省略新字段时保持历史默认值。发布后只影响新创建账号的初始资金与固定档位，已有账号不补币、不重新选档，不修改已保存的请求。新参数不需要数据库结构迁移。

## 直接无奖局回放存储

体验池向经过鉴权的游戏 `/internal/auto-round` 发送 `skipZeroWinReplay=true`。账号分类仍由大厅决定；游戏服不查询大厅数据库或排行榜。原开奖及资金结算流程不变，只在首次基础局单帧直接零派彩结束、且没有免费或后续步骤时跳过回放详情写入。必要票据、幂等、自动任务及统计照常保存，中奖、免费／重转和普通账号行为不变；不采用前 100 或 50 倍条件。

历史体验账号直接无奖回放可使用[游戏存储维护工具](../../slots_service/docs/storage-optimization.md)清理：先导出 account_type=experience 的 UID 快照，明确 appname/appkey，在分批备份后执行；不删除大厅钱包或统计。
