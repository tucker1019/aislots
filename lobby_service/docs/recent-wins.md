# 首页近期大奖

## 入选与统计

一笔付费投注及后续连消、重转、免费局全部结束后，由游戏服已有的
`game_statistics_outbox` 上报整单 `Ticket.Amount / Ticket.TotalWin`。
大厅验证结算合计后写入 `lobby_game_completions`。播报不扫描原始盘面，
不以单帧、单次消除或盈利入选，不限制账号类型，体验账号同样纳入。

入选条件满足任一个：

- 总中奖金额 / 付费本金 >= 20。
- 总中奖金额 >= Rp200.000，且总中奖金额 / 付费本金 >= 5。

接口金额始终为整数分，因此第二个金额阈值为 `20000000`。
SQL 采用 numeric 精确交叉相乘，避免大额 bigint 溢出和倍数四舍五入误入选。

大厅后台任务启动即生成一次快照，此后每分钟生成一次。按整单结束时间倒序、
平台订单号倒序，查询快照时刻前 60 分钟内最新 50 条。最近一分钟不足时自然向前
补齐，最多回溯 60 分钟，不够则返回实际条数。只选已启用且可见的游戏。
配置发布后随运行时快照重建任务。进程退出取消任务；数据库失败保留上次快照，
响应时仍剔除已超过 60 分钟的记录。

迁移 031 添加只包含符合条件订单的部分索引。没有新增盘面副本或统计表；
发布时需为首次创建索引预留时间。

## 协议

由 `game_api.proto` 生成：

- `POST /api/game/recent-wins`：游客提交 `{}`；登录时提交 `uid/sid`。
  返回 `items`（最多 50 条）及 `updatedAt`。
  每条包括稳定 `id`、游戏 ID、两种名称、封面、脱敏昵称、中奖整数分字符串、
  倍数字符串、结束时间、`isSelf`、投注 ID `betId`、投注整数分字符串 `betAmount` 和 `avatarId`。不返回玩家真实 UID 和原始昵称。
- `POST /api/game/recent-wins/replay`：提交列表记录 `id`，返回 `replayUrl`。
  服务端必须在最近发布过的快照中找到该订单，再使用可信 UID、游戏 ID 和投注 ID 调用
  既有 `/internal/rank-replay`；浏览器不能指定其他玩家或投注。
  链接只含回放 ID 与分享令牌，不包含登录票据。回放使用既有完整订单流程。
  发布过的记录保留一小时回放授权，避免下一次统计换掉记录后，仍在客户端队列里的卡片立刻无法回放；这不扩大首页列表的60分钟查询范围。

验证盾牌表示来源为已验证结算的整单记录，不表示第三方审计认证。

## 首页队列

进入 home 请求一次，停留时每分钟刷新一次；离开 home 取消请求、重试及滚动。
home 在游戏页面背后保留挂载时，通过 active 关闭查询，返回 home 再请求。
切账号重建队列，防止“你”标记串号。

新响应单独缓存，不插入或重排当前批次。连续滚动逐个消费当前批次，末尾直接接最新缓存，
例如旧49、旧50、新1、新2，随后新3、新4；无更新时首尾循环。每屏四张卡片，
只自动滚动，不接受拖动或横向手势。查看详情、回放或分享期间暂停，关闭后从原位置继续。
空响应在现有缓冲卡片播完后生效；真实空列表隐藏区块，不伪造中奖。

首次加载及失败重试时显示与卡片同高的 shimmer 骨架。每轮总共最多 5 次请求
（首次 + 4 次重试，延迟 2/4/6/8 秒）；全部失败仍保留骨架，不放错误大面板，
不再继续轮询。重新进入 home 开始新一轮。已有数据时刷新失败保留卡片。
回放请求失败用公共 Toast，重试由再次点击触发。

本区金额独立采用缩写：低于 Rp1.000 显示整数，之后使用 k 和一位小数，向零截断，
不影响余额、投注或其他页面金额。自己的记录显示本地化“你”和轻微底色。

大奖条目包含 betId、betAmount（整数分）和 avatarId，供居中投注详情弹窗展示真实订单、投注额与头像；昵称仍脱敏，不返回玩家 UID。卡片仅打开详情，详情内通过 /api/game/recent-wins/replay 取得授权回放链接。
