# Slots 数值工作台

使用 React、TypeScript 和 Vite 的本地数值工具。数值分析页直接读取和保存项目里的游戏 JSON 文件，没有内置默认配置，也不使用浏览器本地存储恢复数值配置。

## 启动

使用 Node.js 22.12 或更高版本：

```sh
npm install
npm run dev
```

在页面选择游戏 ID，然后点击「读取游戏文件」。首次使用时手动选择游戏；成功读取后记住游戏 ID，下次打开自动从磁盘重新读取该游戏。游戏被删除或文件无效时明确提示，不改用其他游戏。文件读写由 Vite 提供的本地文件服务处理，不需要启动 `slots_service`。

文件服务仅允许本机访问；请保留 Vite 的本机监听方式。构建和预览：

```sh
npm run build
npm run preview
```

`preview` 同样可以读写项目文件。单独将 `dist/` 上传到静态托管不会提供项目文件读写服务，需要在项目目录运行上述本地命令。

## 游戏文件

配置位于 `aislots` 项目根目录，和 `slot_math` 并列：

```text
aislots/
├── game_configs/
│   └── AG1/
│       ├── base.json
│       ├── free.json
│       ├── config.json
│       └── board.json
├── slot_math/
├── slots_service/
└── client/
```

玩法规则在数值分析左侧「基础配置 → 玩法规则」选择并随「保存文件」写入 config.json。ruleType 为必填的带版本标识，不提供缺失时的默认值。当前 Ways 盘面工作区只支持 ways_cascade_v1；连线等规则可先保存配置，生成与验证尚未实现时会明确禁用。服务端从同一文件读取规则，不在部署配置重复维护。

每个游戏目录包含四个配置文件。数值分析使用前三个文件，盘面工具使用 board.json 并读取 config.json 的线数。增加游戏时创建对应 ID 的目录及这四个文件，刷新页面后即可选择。游戏 ID 支持字母、数字、下划线、短横线，最长 64 个字符。

- `base.json`：普通倍率及权重，格式为 `[[倍率, 权重], ...]`。
- `free.json`：免费倍率及权重，格式相同。
- `config.json`：玩法标识 `ruleType`、其余基础配置、高级配置、模拟次数和种子。
- `board.json`：盘面工具的列高、图标库、赔付表、消除加成和检测种子。

两张表均保存原始倍率，不除以线数；实际奖金 = 文件倍率 ÷ 线数 × 总投注。支持重复倍率、小数和零权重，记录顺序保持不变；表不能为空，总权重必须大于零。

`config.json` 的结构示意如下，具体业务数值以各游戏文件为准：

```json
{
  "version": 1,
  "ruleType": "ways_cascade_v1",
  "parameters": {
    "lineCount": 20,
    "baseSpinWinProbability": 0.39,
    "freeSpinWinProbability": 0.52,
    "freeSpinTriggerProbability": 0.0065,
    "freeSpinGuaranteedWin": false,
    "freeSpinAwardWeights": [[8, 300], [10, 75], [12, 15]],
    "lossStreakRtpCompensation": true,
    "freeTriggerRtpCompensation": true,
    "lossStreakRule": {
      "enabled": false,
      "start": 3,
      "probability": 0.41,
      "interval": 2,
      "step": 0.01,
      "cap": 9
    },
    "winStreakRule": {
      "enabled": false,
      "start": 2,
      "probability": 0.35,
      "interval": 1,
      "step": 0.02,
      "cap": 5
    },
    "freeTriggerRule": {
      "enabled": false,
      "start": 100,
      "interval": 20,
      "step": 0.002,
      "cap": 200
    }
  },
  "simulationOptions": { "paidSpins": 1000000, "seed": 42 }
}
```

文件中的概率使用 0～1 的数字，页面使用百分数。例如 `0.0065` 在页面显示为 `0.65%`；策略 `step: 0.002` 表示每档增加 0.2 个百分点。

`freeRetriggerLimit` 可选：省略表示不限制追加次数，0 表示禁止追加，正整数表示每段免费最多追加次数（最大 100）。首次触发不计入追加次数。

普通连续策略通过 `enabled` 控制；未配置的策略不会自动补入业务数值。免费触发策略只保存开关、起始局数、间隔、增量和封顶局数；从基础触发率加一个增量开始提升，不保存旧的起始概率或重置概率。模拟种子为 `null` 时，每次启动随机生成种子。

## 读取、应用与保存

1. 选择游戏并点击「读取游戏文件」，加载数值配置；盘面工具另行加载同一游戏的 board.json。两页共享当前游戏和上次成功读取的游戏 ID。
2. 修改参数或在倍率编辑器中确认修改，页面显示未保存状态；此时磁盘文件保持原样。
3. 点击「应用配置」，更新理论计算和后续模拟使用的完整配置快照。
4. 点击「保存文件」，将当前有效配置写回当前游戏目录。保存与应用独立，不会改变正在运行或已经完成的模拟快照。

没有配置文件时不会生成或回退到默认配置。无效 JSON、缺失字段、错误倍率和不可计算的策略会明确报错。保存失败保留页面修改；重新读取有未保存修改时需要确认丢弃；切换游戏会检查数值分析和盘面工具两页的修改。

保存前检查文件版本。其他窗口或外部编辑器修改文件后，旧页面保存会被拒绝，需重新读取后再编辑。保存先写临时文件，再逐个替换目标文件；替换失败时恢复已替换的文件并报告错误。它不是跨文件系统事务，不能保证进程或设备突然中断时三个文件同时切换。

数值配置和模拟选项不再写入 `localStorage`。浏览器只保留上次成功读取的游戏 ID 和菜单展开状态；旧的浏览器数值记录不会作为配置来源。页面关闭或刷新后，未保存的修改不会恢复。

## 数值分析与模拟

- 理论计算支持普通、免费和总 RTP，奖金均值、方差、标准差及平均中奖指标。
- 普通局先判断中奖，再按倍率区间和档内权重抽倍率；免费触发独立判断，无普通奖金也能触发免费。
- 首次赠送免费局数及追加局数均按配置权重独立抽取；支持随机位置保底和追加次数限制。
- 连续输赢策略只累计付费局。普通正奖金或触发免费均算中奖，免费内部旋转不计数。
- 连续未中奖提概率时，可通过调整普通奖第一档区间总权重补偿 Base RTP；免费触发提概率时，可降低整段免费自然中奖率补偿 Free RTP。
- 模拟在 Web Worker 中执行，支持种子复现、分块进度和取消；只提交完整付费流程的统计。
- 统计包含区间抽样、策略档位、最大连续输赢、免费等待分布、赠送局数分布和最高观测倍率。
- 使用长期边际方差描述单付费局奖金；启用连续策略后，不可直接乘局数作为累计奖金方差。

## 盘面工具（开发页）

打开 `#/developer`，和数值分析页共用当前游戏。页面不再读取浏览器中的旧开发配置，没有演示默认配置，也没有配置导入导出。

盘面配置示意：

```json
{
  "version": 1,
  "fillWeightIncrement": 0,
  "scatterWeightIncrement": 0,
  "columnHeights": [4, 4, 4, 4, 4],
  "cascadeFactors": [1, 2, 3, 5],
  "freeCascadeFactors": [2, 4, 6, 10],
  "symbols": [],
  "gold": { "columns": [], "baseProbability": 0, "freeProbability": 0, "wildSymbolId": null },
  "seed": null
}
```

AG1 的 board.json 已按麻将规则配置九种普通图标、百搭和预留分散图标。每个图标保存唯一 `id`、名称 `name`、颜色 `color`、抽取权重 `weight`、类型 `role`、按连续列数索引的原始赔付 `payouts`。类型为 `normal`、`wild` 或预留的 `scatter`；百搭权重必须为0；免费图标权重用于骨架外补空，不参与中奖骨架的初始生成和补充采样。

线数只在 config.json 维护，开发页只读。数值分析保存新的线数后，开发页同步线数并清空旧检测流程，保留盘面配置草稿。页面赔率输入与文件均使用原始单位，例如输入 3，实际为 3 ÷ 线数；最终乘 Ways 数量和本轮加成。不重复归一化。

支持增删列、调整列高、图标和赔付编辑、按权重生成、手动布盘、单步与自动检测。Ways 从最左列连续至少 3 列，只取最长连续列数赔付；共享百搭分别计奖，中奖位置并集只消除一次。幸存图标保持顺序下落，顶部补齐。普通加成 `cascadeFactors` 与免费加成 `freeCascadeFactors` 独立配置、独立增删档位，不存在固定倍数关系。检测时选择普通或免费模式，每次从对应第一档开始，超过档数沿用对应末档；模式选择加成表与金底概率，不执行免费流程。

金底配置保存在 `gold`：`columns` 为从 1 开始的轴号，`baseProbability`、`freeProbability` 为 0–1 的概率，`wildSymbolId` 指向转换后的百搭。AG1 仅第 2、3、4 轴有金底，普通概率 0.083、免费概率 0.11；每个初始或补充格子按权重抽基础图标，再独立判断金底。启用金底时基础图标 ID 使用 1–999 的整数字符串，金底 ID 为基础 ID 加 1000，不额外保存权重和赔付；例如三饼 `1` 对应金底三饼 `1001`。

金底按基础图标参与 Ways，中奖后在原格转为百搭，再随幸存图标一起掉落；新百搭从下一轮参与判奖，中奖后正常移除，不再转换。未中奖金底保持不变。逐轮结果分别记录 `removedIds`（实际移除）、`transformedIds`（金底转百搭，保留格子 ID）、`refillIds`（顶部新增），支持回看与检查。百搭不能直接抽出；手动布盘可勾选「金底」放置，轴号和图标 ID 同样会校验。

本工具不判断免费概率，不赠送或追加免费局。是否命中免费及赠送局数由数值模型和未来的开奖流程负责，工作区可指定免费表现目标，补空按下述免费图标规则执行。

点击「保存盘面配置」仅写回 board.json，不改变数值配置或两张倍率表；数值分析保存也不会覆盖 board.json。两种文件分别检查各自版本，避免相互干扰；盘面配置外部修改时会拒绝旧版本覆盖。

棋盘形状和图标库可以为空库阶段保存，随机生成则要求普通图标存在正权重。检测中的棋盘、每轮结果和手动布盘不写入配置文件。单次检测最多 100 轮消除，超过上限明确停止，不标为完整结果。批量生成功能见下文。

## 中奖骨架盘面库

开发页的「生成盘面库」支持普通 / 免费单次消除链，填写生成局数（最多1亿）、每倍率保留条数和可选种子。先保存当前盘面配置再生成。后台 Worker 执行计算，提供实时统计和「停止并保留结果」；仅已完整结束的中奖链入库，未中奖和达到100轮上限的结果不保存。此处不使用数值模型的中奖概率或免费触发概率：生成的是按图标权重产生的自然盘面，倍率表在未来开奖时决定选中哪个倍率桶。

每倍率保存不同骨架；桶满后随机替换候选以保留多样性，并非自然开奖概率的存储。全局最多保留10万条，骨架JSON文本预算32 MiB，达到容量后继续统计但不再扩张样本。倍率种类超过10000时停止并报错。生成1亿局需要实际逐局计算，工具不承诺即时完成；可以停止后保存部分结果。当前不支持断点续跑或跨批合并。

保存位置：`game_libraries/<gameId>/<base|free>/<独立批次>/library.json`。每次保存创建新批次，不覆盖旧库或任何游戏配置。数据文件只有「原始累计倍率 → 多条骨架」：

```json
{"4":[[3,0,1,2,1001,4,1,2,0,3,4,3,0]]}
```

每条骨架按阶段串联：`[固定数量, 位置, 图标ID, ...]`。第一段为初始盘面，之后每段对应一次消除后的顶部补充。位置为整个盘面按列、从上到下排列的零基下标；补充阶段的位置指向掉落补齐后的盘面，且必须是本轮新补格。图标ID保存为整数，金底为基础ID+1000。

末尾`0`表示最后一次补充没有固定中奖图标，剩余格子交给未来服务端填充成不再中奖的盘面。必须按数组边界解析：中间也可能出现`0`，表示这轮没有固定新补图标，但已有图标掉落后仍会继续中奖，不能提前截断。库中保留整条链中任何时候中奖的图标在其出生阶段的值；金底转出的百搭不重复保存，由规则重建。

每条入库骨架会用空位重放验证：固定图标均确实参与中奖、每次补充位置合法、消除链完整、最终原始倍率精确匹配。倍率键使用配置十进制值的整数运算生成，避免浮点尾数分桶；不乘投注、不除线数。保存时服务端再次重放校验，并拒绝已过期的盘面配置版本。

同批次 `manifest.json` 保存模式、种子、生成统计、是否部分完成、配置快照、配置和数据SHA256、格式版本。纯倍率JSON保持紧凑，部署时应与该清单一起使用。

盘面库仍保存纯中奖骨架；开发页已支持下面的受约束补空预览和效果对比，服务端按需加载后续实现。服务端补空必须保留固定图标、验证填入图标没有额外参与中奖、完整走完消除链并核对最终倍率，不能直接把任意随机填充的结果返回客户端。


## 棋盘补空与量化对比

`board.json` 的 `fillWeightIncrement` 为每次补中某普通图标后累加的绝对权重 n，范围0–10亿。AG1 初始配置为100，左侧「补空规则」中可修改，点击「保存盘面配置」写回文件；「补空策略与效果对比」只读显示此配置；n=0表示不强化。无内置业务回退值，缺失字段会提示配置错误。

工作区「生成随机盘面」先按原有图标权重生成完整参考中奖链，再固定整条链中的中奖图标，补齐其他位置；「按补空策略填满」展示这条经过整局验证的初始盘面，再点「从当前盘面测试」可播放同一条链。手动布盘中的已有格子不改动，只补空格及后续新空位。逐轮检测播放的是已经通过验证的补充过程。

按列、从上到下填空，初始权重取普通图标配置；抽中后该图标权重加n，换列和进入后续消除补充阶段均不重置，新的一局重置。固定图标不增加补空权重。当前中奖图标从补空池中排除，百搭不能直接抽出；免费图标按独立权重规则补入，金底仍按当前普通/免费概率生成。

候选排除同时考虑固定骨架、已有图标、百搭替代及该图标所有后续掉落位置，候选不得增加中奖图标、中奖格数、Ways或延长中奖列数。出现空候选池时重新尝试整局，最多64次；仍失败明确报错，不使用改变奖金的回退结果。每次输出再完整验证整条链及累计奖金与参考链一致。初始盘面、每次补充后都验证；最后补齐后必须没有后续中奖。

「对比补空效果」后台生成同一批参考骨架，两组分别关闭普通/免费额外加权和读取左侧当前配置，使用相同补空随机种子进行对比，运行时使用配置快照，模拟区域不提供n的独立编辑入口。展示单组成功/失败数；表现比例仅统计两组均成功的同一批骨架，避免失败导致样本口径不一致。统计指标：

- 差一列盘面率：非中奖普通图标在第1、2列均可匹配（含金底与百搭），第3列不可匹配；具有至少一个该类图标的盘面数除以所有观察盘面数。
- 前三高赔差一列率：上述图标中，至少一个属于按3列原始赔率排序的前三图标。
- 同列重复率：每列每种普通图标数量扣除首个之后的格数，除以普通图标总格数；金底和原图标合并，百搭不计。
- 通过样本奖金一致率：验证通过的补空结果与参考奖金一致的比例。失败单独报告，不算作通过。
- 平均尝试次数、平均补空耗时：按单组补空成功样本计算。

观察盘面包括初始盘面和每轮补充后的盘面，完整消除链可能贡献多个观察盘面。对比数量最多10000局，支持停止；种子沿用工作区输入，留空时随机。增加n不保证每个指标都单调提高，应看对比结果与失败、耗时成本。


### 免费图标补空

免费图标的基础补空权重是图标库中`role=scatter`的`weight`，左侧「补空规则」和图标库编辑共用同一字段；`scatterWeightIncrement`为独立的免费换列加权n，均保存在board.json。AG1 本次设置分散基础权重300、免费加权100。基础权重为0表示关闭随机免费补空，不会靠加权重新启用。

首轮第1列使用基础免费权重；之后每列（含后续消除补充的第1列）重新使用「基础权重＋免费n」，不累加成基础＋2n、基础＋3n。每次初始填充或消除补充，每列最多新增1个，抽中后本列本轮移除所有免费候选。进入下一列恢复候选。已有免费图标正常保留、掉落，不占下一轮新增名额，所以一列可经过多轮累积多个。免费图标不会清空普通图标的累计权重，也不享受普通图标的抽中累计加权。

未中免费整条链累计最多2个，达到上限立即从所有后续候选池移除。工作区「免费表现（仅测试）」可选未中免费或已中免费3/4/5个；该选择是本次运行输入，不是触发概率配置。命中目标时，按权重补入并预留每列每轮名额，剩余名额恰好够目标时补足，保证最后数量准确；没有足够骨架外新格或基础免费权重为0时明确报错。手动固定图标同样计入初始数量和整局上限，初始同列多个免费图标会被拒绝。

批量骨架生成始终仅采样普通图标，不保存免费图标或免费触发流程。补空后的免费图标全程不参与消除和金底转换，完整中奖链和奖金仍须与原骨架一致。效果对比增加「两免费图标盘面率」，统计观察盘面中恰有2个免费图标的比例；两组共用相同免费表现目标，基准组关闭普通与免费两项额外加权。
