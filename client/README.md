# Cocos 机台迁移规范

以后把原版游戏接入 AISlots，按下面的顺序做。**先完整复制、读懂原版数据流、留好对照，再换接口；跑通后才删旧代码和资源。** 迁移的目标是保留原版玩法和演出，接入我们的 Go 机台、大厅和通用界面。单场景、启动页、弹窗等明确约定的改动单独处理。

## 1. 完整复制，建立对照

- 整个项目复制到 `client/<游戏英文名>/`，例如 `client/fortunetiger/`。目录用游戏名，`AG4` 这类编号作为独立的 `gameId`。先保留完整源码、场景、资源、`.meta`、项目设置和模板；构建产物及编辑器缓存重新生成。不要做到一半才从原版找资源，或顺手重建动画。
- 保留一份未改动的原版作为对照。用本项目支持的 Creator 版本打开副本（AG4 为 3.8.5）；把版本迁移与业务改动分开核对。检查脚本组件、Prefab、Spine、材质、动画事件和字体引用是否正常导入。
- 原服务器不可用时，从原协议定义、消息处理、原版结果样本和离线构建还原流程。记录哪些效果已用样本验证，哪些还需要验收；不能把猜测当作原版行为。

## 2. 先读数据流，再定映射

从原版的「收包 → 解析 → 控制器 → 动画 → UI」追一遍完整流程。给每种玩法留下可重放的样本和映射记录，至少注明：

| 核对项 | 要写清楚的内容 |
| --- | --- |
| 开局、恢复 | 默认盘面、上局盘面、空位、滚动缓冲格分别取哪里；组件何时创建、何时刷盘 |
| 下注、停轴 | 哪一刻起转、何时允许停轴，盘面列行顺序、符号 ID、格子 ID、中奖线如何映射 |
| 特殊玩法 | 消除、免费、重转如何进入、逐轮推进和退出；锁格、换背景、角色、音效、倍率、大奖在什么事件播放 |
| 结算 | 余额、当前轮奖金、整局 WIN、每条线金额各用哪个字段，什么时候更新 |
| 历史与回放 | 首屏从哪张盘面起转、每一步播什么、什么时候结束，哪些字段必须隐藏 |

动态效果尽量沿用原版的控制器、动画状态机和资源。把 Go 数据到展示结构的转换集中在适配器，不为迁移重写转轴、角色或派奖演出。AG4 实例见 [FTResultAdapter](fortunetiger/assets/fortunetiger/src/game/net/FTResultAdapter.ts) 和 [FTCenterRollCtrl](fortunetiger/assets/fortunetiger/src/game/view/layer/FTCenterRollCtrl.ts)。

## 3. 接大厅和 Go 机台

- 大厅 `/api/game/launch` 签发 `launchTicket`，客户端用票据、`exchangeId` 和 `gameId` 调机台 `POST /api/v1/login`。兑换成功后把游戏 token 保存在当前标签页的 `sessionStorage`（按 API 地址和 gameId 分隔），清掉 URL 中的票据。兑换重试复用 `exchangeId`；会话过期按项目流程返回大厅。保留当前大厅嵌入的退出消息和回放通信。
- 初始化读 `bets`、`state`。投注档位、线数、最大 `betLevel` 走配置；按 `bet × betLevel × lineCount` 计算总注。候选总注去重，重复时取最低 `betLevel`。服务端按整数分记账，界面统一按 `amountScale` 格式化（两位时除以 100）；字段类型以接口协议为准。
- 金额不足时在客户端直接提示，转轴不启动，也不请求 `spin`。正常投注先起转，再等服务端返回当前结果才停轴。首次请求号来自 `state`，成功后使用 `nextRequestId`；超时重试复用原请求号和原下注参数，避免重复扣款、派奖或推进。
- 每个玩法按 `nextAction` 推进，不能把消除步骤误当成新一轮旋转。**AG4 重转是具体实例**：首次 `spin` 命中重转就返回第一轮真实结果，不额外插入空盘；后续每轮先起转，再请求，收到当前盘面才停轴。首轮实际无新增也可能空盘结束。整局扣一次，末轮派奖；实玩不提前拉整局结果。
- 服务端是盘面、中奖和结算的唯一来源。按该游戏规则展示预览格、装饰格、锁定与新增数据；AG1～AG3 的底部格子按 [帧一致性规范](../.agents/skills/game-frame-consistency/SKILL.md) 保存与恢复，不套到 AG4 的 3×3 盘面上。数值、盘面库、规则版本和大厅入口要与新 `gameId` 独立配套，详见 [机台协议](../slots_service/docs/client-api.md) 和 [大厅接入](../lobby_service/docs/game-integration.md)。

## 4. 做单场景和通用界面

- 构建和编辑器预览都用同一主场景。对照 AG3/AG4 的「AG 开场动画 → 封面与加载进度 → START → launch 铺满 → 游戏」交接。AG 动画退场时封面继续覆盖；点 START 后才进入 launch 过渡，等游戏首帧绘制后再移除遮挡。
- `jdt1.png` 为进度条底图，`jdt.png` 为填充。进度来自实际预加载和初始化；保持素材宽高比，START 的位置、圆角跟参考项目一致。Web Mobile 和 Preview 两套模板一起改，验收窄屏、宽屏、全屏切换和缩回。按需加载的特效资源仍在触发时加载，使用该游戏的进度与释放流程。
- Alert、玩法说明、投注档位、自动旋转、投注历史等通用界面参考 AG3 的 HTML 实现，玩法内容用本游戏数据。操作失败用统一 Toast，需确认或重试时用 HTML Alert；不要塞错误文本改变正常布局。弹窗贴合可视游戏区域，关闭或离开场景时清理。
- 旧预制体和现行菜单是两件事。例如 AG4 删除了 `panel_menu`，底栏的菜单入口、声音、玩法、历史和退出仍要可用。

## 5. 恢复和回放

- 正常进场从 `state.lastFrame` 恢复盘面。上一局已完成时，同时显示其 `totalWinAmount` 和已保存的中奖线，用原有连线动画；未中奖显示 0，没有历史时才用默认盘面。进场展示不触发下注、结算或整局重播。
- 上一局未完成时，从最近已保存的盘面和下一请求号直接继续，已完成的轮次不再播放或结算。
- 回放是只读流程。起转前先显示该笔记录的 `startBoard`（上一笔最终盘面）；没记录才用默认盘面。**先从上一局盘面起转，再停到本次首帧**，按历史中的已结算帧依序播放；不拿当前玩家的 `state` 当回放起点，也不调用 live `spin`。个人、分享和大厅排行榜的回放都验。回放余额按 AG3 样式显示 `******`，重播和结束时也要保持；投注和本局 WIN 仍正常显示。

## 6. 确认替代入口可用后再清理

- 删除旧入口和多余场景、WebSocket 收发/心跳/编解码、旧平台 GameBridge。现代大厅票据、退出和回放通信仍在使用，单独核对。
- 删除已被替换的 AlertLayer、旧 `panel_auto`、`panel_balance`、`panel_bet`、`panel_rule`、`panel_menu` 和它们独占的资源。去掉旧平台字体（如 AG4 的 `singincom/font`），受影响文字切系统字体，保留游戏仍在用的位图数字等素材。
- 用 Cocos 的 UUID（包括压缩 UUID）、代码动态加载路径、Spine/图集/动画引用、HTML/CSS 和构建模板一起排查；只删确认无引用的资源和对应 `.meta`。把旧场景从构建配置里去掉，检查是否还有脚本或模板依赖旧节点。

## 7. 本地验收再发布

- 用对应 Creator 版本构建，实际从大厅进入，用新产物验收；预览和 Web Mobile 都要跑。检查 START、封面、底栏、弹窗和横竖屏切换，无缺资源、脚本错误、旧平台请求或 WebSocket。
- 用可复现样本验普通不中奖、普通中奖、大奖、该游戏的特殊玩法；比对每一轮的盘面、停轴、角色与音效、中奖线和最终 WIN。覆盖慢响应、同请求号重试、余额不足零请求、刷新已完成与未完成、旧订单回放。
- 上架时核对大厅游戏入口、对应静态目录、机台配置/盘面库版本与环境路由；Web Mobile 资源使用内容哈希，线上 API 使用部署配置。部署后通过大厅打开，验证加载的确是新产物。发布方法见 [测试环境部署说明](../deploy/test/README.md)；本地构建不等于已发布。

迁移交付至少留下：原版对照及样本说明、字段到动画的映射、删除范围、浏览器验收结果。另见 [AG4 项目说明](fortunetiger/README.md)。

## 印尼市场的 HTML 与金币展示

- 游戏 HTML 界面统一使用印尼语：投注、自动旋转、规则、记录、回放、分享、重试和提示弹窗，以及加载封面的按钮与无障碍文案。Cocos 场景文字和图片文字单独按需求调整，不通过翻译改动资源路径、节点名或协议字段。
- AG1～AG9 的客户端金额展示使用印尼千位分隔、不显示小数、不加 `Rp`，例如 `18.030`。只在展示时向零截去小数；接口仍传原始整数分，不能用显示字符串作为下注金额或结算依据。
- 余额、投注、派彩、大奖计数、历史和回放均使用同一口径；单线投注等分数金额也显示整数。RTP、中奖倍率、符号赔率和费率保留必要精度，不按金额截断。
- 历史大金额使用 BigInt 计算，避免先转 Number 丢失整数精度。兼容旧代码中仅读取显示金额的动画时，千位点号必须按印尼格式移除，不得当作小数点。
- 可运行 `node --test client/tests/indonesian-display.test.cjs` 检查现有各机台展示契约。当前仓库客户端覆盖 AG1～AG8，AG9 接入客户端时必须遵守同一规则。
